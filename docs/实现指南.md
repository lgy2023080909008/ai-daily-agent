# 从零搭建 ai-daily-agent：9 个阶段

> 写给第一次独立做完一个 Agent 项目的人。
> 原则：**每个阶段结束都必须有一个能跑的命令和可见的输出**，跑不通就不要往下走。
> 按顺序做，每阶段结束 `git commit` 一次，最后你的 commit 历史本身就是"我怎么做的"证据。

---

## 阶段 0 · 开工前（30 分钟）

**目标**：环境干净，能装包，项目目录建好。

1. PyCharm → `New Project` → 选 `Virtualenv`，Python 3.11 或 3.12（**别用 3.13**，部分依赖还没跟上）。
2. 建目录（PyCharm 右键 New → Directory）：

```
ai-daily-agent/
├── aidaily/
│   ├── fetchers/
│   ├── pipeline/
│   └── notifiers/
├── tests/
├── eval/
├── docs/
├── data/
└── .github/workflows/
```

3. 根目录建 `requirements.txt`，粘贴仓库里的版本，然后：

```bash
pip install -r requirements.txt
python -c "import langchain_core, langchain_openai, requests, pydantic, pydantic_settings; print('ok')"
```

4. `git init`，建 `.gitignore`（**先建再写代码**，否则很容易把 `.venv` 提交上去）。

**验收**：`python -c "..."` 打印 `ok`。

**常见坑**
- PyCharm 装了包装不上：检查右下角解释器是不是你新建的 venv，不是就 `Settings → Project → Python Interpreter` 切过去。
- 国内装包慢：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`。

## 阶段 1 · 骨架先跑起来（1 小时）

**目标**：还没有任何业务逻辑，但 `python -m aidaily` 能打印一行字。

要写的文件：
- `aidaily/__init__.py`（版本号）
- `aidaily/config.py`（全部配置集中在这里，从 `.env` 读）
- `aidaily/models.py`（`RawDoc` / `Doc` / `ScoreResult` / `DigestItem`）
- `aidaily/__main__.py`（argparse，先只打印 "hello"）

**为什么先写 models**：数据结构定下来，后面每个模块的输入输出都是确定的。面试官问"你这个项目的数据流"，你能画出 `RawDoc → Doc → DigestItem` 这条线，就已经赢了一半。

关键点：`Doc.id = sha1(标题)`，**用标题算 id 而不是 url**，因为同一篇论文在不同源的 url 不同、标题往往一样，id 相同就天然去重。

**验收**

```bash
python -m aidaily
# 输出：aidaily v0.1.0
```

**commit**：`chore: 项目骨架与配置`

## 阶段 2 · 接第一个数据源（2 小时）

**目标**：真的能从 arXiv 抓到 20 条论文，打印标题。

要写的文件：`aidaily/fetchers/base.py`、`aidaily/fetchers/arxiv.py`

**先只做一个源，而且选最稳的 arXiv。** 不要一上来四个源一起写，你会分不清是解析错了还是网络错了。

关键技术点：
1. arXiv 是 **Atom XML**，用标准库 `xml.etree.ElementTree` 解析，不要引额外依赖。
2. 标题里常有换行，必须 `" ".join(text.split())` 压平，否则去重会失效。
3. `base.py` 里就把**重试 + 缓存兜底**写好：

```python
for attempt in range(1, max_retries + 1):
    try:
        docs = self._fetch()
        self._write_cache(docs)      # 成功就缓存
        return docs
    except Exception:
        self.sleep(min(2 ** attempt, 8))   # 指数退避
return self._read_cache()            # 全失败用缓存
```

这段是整个项目"工程感"最强的地方，**面试一定会问**："如果某天 arXiv 挂了怎么办？"

**验收**

```bash
python -c "from aidaily.config import load_settings; from aidaily.fetchers.arxiv import ArxivFetcher; d=ArxivFetcher(load_settings()).fetch(); print(len(d)); print(d[0].title)"
```

期望：打印 30+，第一条是最近提交的论文标题。

**常见坑**
- `403` / 超时：arXiv 对 UA 敏感，`requests.get` 里带上 `User-Agent`。
- 抓到 0 条：`search_query` 里的 `cat:` 分类写错，或 `sortBy=submittedDate` 拼错。
- 解析报错但网络正常：先 `print(resp.text[:500])` 看返回的是不是 HTML 错误页。

**commit**：`feat: arXiv 抓取器 + 重试与缓存兜底`

## 阶段 3 · 入库与去重（2 小时）

**目标**：同一篇内容跑两次，第二次不会再出现在结果里。

要写的文件：`aidaily/db.py`

表就一张，重点三个字段：`id`（主键）、`digest_date`（非空表示已推送）、`score`。

```sql
CREATE TABLE IF NOT EXISTS docs (
  id TEXT PRIMARY KEY, source TEXT, title TEXT, url TEXT,
  relevance INTEGER, novelty INTEGER, score REAL,
  digest_date TEXT, created_at TEXT
);
```

**核心规则写在代码注释里，也写在 README 里**：`add_doc()` 返回 `True` 才说明是"没见过的新内容"。
这一个小设计解决了"日报每天重复推同一篇"这个最难看的 bug。

**验收**

```bash
python -c "
from aidaily.db import Store
from aidaily.models import Doc, RawDoc
s = Store('data/test.db')
d = Doc.from_raw(RawDoc(source='t', title='同一个标题', url='u'))
print(s.add_doc(d), s.add_doc(d), s.count())
"
# True False 1
```

**commit**：`feat: SQLite 存储与已推去重`

## 阶段 4 · 扩到四个源（3 小时）

**目标**：arXiv + Hugging Face + GitHub + RSS 都能抓到，且**任何一个源挂掉不影响其他源**。

要写的文件：`fetchers/huggingface.py`、`fetchers/github.py`、`fetchers/rss.py`、`fetchers/__init__.py`

三个源的注意点：

| 源 | 接口 | 坑 |
| --- | --- | --- |
| Hugging Face | `https://huggingface.co/api/daily_papers` | 返回 JSON 是列表，字段在 `item["paper"]` 里，要做 `.get` 兜底 |
| GitHub | `search/repositories?q=created:>=日期` | 官方**没有** trending API，网页爬虫一周就挂；search API 未认证限 10 次/分钟，所以只请求一次 |
| RSS | 标准库 `xml.etree` 解析 RSS 2.0 / Atom | 一个抓取器吃多个 url，单个坏了 `try/except` 跳过；混杂站点先用关键词过滤省 token；不引 feedparser 是为了少一个依赖 |

`fetchers/__init__.py` 里 `fetch_all()` 用 try/except 包住每个抓取器——**这是一个必须有的设计，不是防御性编程洁癖**。

**验收**

```bash
python -c "from aidaily.config import load_settings; from aidaily.fetchers import fetch_all; docs=fetch_all(load_settings()); import collections; print(len(docs)); print(collections.Counter(d.source for d in docs))"
```

期望：总数 80+，能看到 4 个 key。

把某个 RSS 地址改成一个不存在的域名再跑一次，**必须还能出结果**（只是少了那个源）——这就是验收标准。

**commit**：`feat: 接入 HF / GitHub / RSS 多源抓取`

## 阶段 5 · 去重算法（2 小时）

**目标**：两篇讲同一件事、标题略有不同的内容，只留一条。

要写的文件：`aidaily/pipeline/dedup.py`

实现分两层，**顺序不能反**：

1. **id 精确去重**：O(n)，先做，成本几乎为零。
2. **相似度去重**：对每条和"已保留"的比一遍，超阈值就丢。

相似度默认用**字符 bigram 的 Jaccard**：零依赖、可解释、中英文都能用。

```python
def bigrams(text):  # "大模型推理" → {"大模","模型","型推","推理"}
    norm = normalize(text)
    return {norm[i:i+2] for i in range(len(norm)-1)}
```

**为什么不用现成的 embedding**：不是不会，而是"先能跑"。等链路跑通、有标注集了，
再切 `DEDUP_MODE=embedding`，这时你才有能力判断切过去到底值不值。**这个先后顺序面试时可以主动讲。**

**验收（写测试，不靠肉眼）**

```bash
pytest tests/test_dedup.py -v
```

期望：`6 passed`。

**commit**：`feat: 两级去重（精确 + 相似度）`

## 阶段 6 · 让模型直接挑（3 小时）

**目标**：从候选里直接得到"今天最值得看的 5 条"，而不是一堆分数。

要写的文件：`aidaily/llm.py`、`aidaily/pipeline/select.py`

先说这一步最值钱的经验：**别让模型逐条打 1-5 分**。
实测它会慷慨地给每条都打 4 分，分数挤在一起，阈值怎么调都分不开。
改成"从 30 条候选里挑 5 条并排序"——模型必须做取舍，判断立刻变准。

prompt 里要放三样东西：

1. **读者画像**（准备面试的本科生、每天 10 分钟）——决定"对谁有用"；
2. **候选编号 + 热度**（GitHub star、HF 点赞）——给它客观旁证；
3. **排除清单**（硬件参数、融资人事、课程广告）——明确什么不要。

```python
result = client.json(SELECT_SYSTEM, build_candidates_prompt(docs), RankResult)
# {"picks": [{"index": 3, "reason": "开源权重 + benchmark 提升"}, ...]}
```

三条必须做的健壮性处理：

1. **index 校验**：模型会编造编号或重复选，越界/重复直接丢弃；
2. **数量补齐**：不够 N 条时按热度 + 新鲜度补位，不能少给；
3. **整体失败**：退回规则排序的同时给上层 `used_fallback` 标记，
   让 CLI 报错——宁可失败，也不要悄悄发一份没挑过的日报。

**没有 API key 怎么办**：`LLMClient(None)` 走 mock，按候选编号顺序取前几条。链路照样跑通、测试照样过。

**验收**

```bash
python -m aidaily --demo                 # mock
python -m aidaily --dry-run --top 5      # 真实模型
```

期望：日志出现 `精选 5 条：xxx / yyy`，且选中的确实是当天最值得看的。

**常见坑**
- 模型返回的 JSON 带 ```json 代码块或前后废话 → `extract_json()` 处理；
  **prompt 里的 JSON 示例必须是单层花括号**，写成 `{{...}}` 模型会照抄，解析必挂（真踩过）。
- 报 `process() takes no keyword arguments` → `LLM_BACKEND=http` 或锁依赖版本，见 README。
- 选出来总是"大厂新闻"、细分论文全被压掉 → 说明读者画像起作用了；
  想让它多收论文就改画像，别去改代码。

**commit**：`feat: 模型精选 Top N 与结构化输出`

## 阶段 6.5 · 预筛：别把 70 条全塞给模型（2 小时，但很值）

**目标**：候选从 70 条砍到 30 条，精选只要一次调用。

这一步不该一开始就做——**先跑通全量版本，量出真实成本，再优化**。

要写的文件：`aidaily/pipeline/prerank.py`

预筛只用免费信号：

```python
score  = min(关键词命中数, 10) * 1.0
score += 来源权重(arxiv 1.0 / hf 1.2 / rss 0.7) * 2.0
score += min(log10(star + 1) * 1.5, 5.0)   # 热度取对数，避免一个爆款压制全部
score += 2.0 if 24 小时内 else -1.0 if 3 天以上
score -= 1.0 if 摘要短于 80 字
```

**验收**：日志出现 `预筛：71 条 → 送模型 30 条`。

**面试怎么讲**：先全量、再量成本、再优化——"我知道每一步省了多少"，而不是"我抄了个优化"。

**目标**：手机真的收到日报；每天自动跑。

要写的文件：`aidaily/notifiers/console.py`、`wecom.py`、`serverchan.py`、`.github/workflows/daily.yml`

## 阶段 9 · 评测（可选，想做才做）

**目标**：能说出"模型挑的这 5 条里，有几条是你真觉得有用的"，而不是"我觉得还行"。

**这一步是可选的**：主流程不依赖标注，跑通前面 8 个阶段就能每天收日报。
只有当你想量化"模型选得准不准"、或者想调 prompt 时，才需要做。

要写的文件：`eval/labeled.csv`（现成的工具已经写好）

```bash
python -m eval.export_for_labeling --add 100   # 从库里导出待标注清单
python -m eval.label_tool                      # 终端里一条条按 1/0，随时退出续标
python -m eval.run_eval                        # 算「精选 5 条命中几条」
```

每条只问自己一个问题：**"如果今天只推这一条，我会觉得有用吗？"** 会 = 1，不会 = 0。
每条 5 秒，100 条约 20 分钟。

输出三个数：

| 指标 | 含义 |
| --- | --- |
| precision@N | 精选 N 条里，你标"值得"的比例 |
| recall@N | 值得看的内容被精选捞到的比例 |
| **比随机好多少** | 减去"正样本占比"这个随机基线，**这个数才说明模型真的有用** |

> 注意：k 比正样本数小的时候 recall 会虚低（前 5 条最多只能捞到 5 个正样本），
> 看 `precision@N` 和 `比随机好多少` 就够了。

**验收**：`eval/results/latest.md` 里有真实数字。

**commit**：`feat: 精选效果评测（precision@N）`

## 附：面试对应表

| 面试官会问 | 代码在哪 | 怎么答（一句话） |
| --- | --- | --- |
| 你这个 Agent 的"Agent"体现在哪？ | `main.py` | 有抓取工具层、有模型基于热度与相关度做的选择决策、有失败重试与降级，不是一次性 prompt 调用 |
| 怎么保证不重复推？ | `db.py` + `dedup.py` | 两层：id 精确去重 + 标题/摘要相似度；再加 SQLite 的已推标记 |
| 某个源挂了怎么办？ | `fetchers/base.py` | 指数退避重试 3 次，仍失败读上次缓存，单源异常被 `fetch_all` 兜住 |
| 为什么不让模型打分再排序？ | `pipeline/select.py` | 实测逐条打 1-5 分会给每条都打 4 分，改成让它从候选里挑 Top N，相对比较比绝对评分可靠 |
| 热度从哪来？ | `fetchers/github.py`、`huggingface.py` | 用源给的客观数字（star、点赞）；没有浏览数据的源就留空，不编造 |
| 模型输出不是 JSON 怎么办？ | `llm.py: extract_json` | 代码块、前后废话、尾逗号三种脏输出都能吃；再失败降级为最低分 |
| 一天 70 条全评是不是很贵？ | `pipeline/prerank.py` | 规则预筛砍到 20 条 + 5 条一批调用，调用次数从 71 降到 4 |
| SDK 版本不兼容怎么办？ | `llm.py` 双后端 | ChatOpenAI 与 requests 两套实现，运行时按错误类型自动切换 |
| 整轮失败了内容会不会丢？ | `main.py` + `db.delete_docs` | 失败回滚本轮入库条目，下次还能重抓重评 |
| 你的效果怎么衡量？ | `eval/` | 300 条人工标注，precision@10 + 正负样本分差 |
| 为什么不用向量去重？ | `dedup.py` | 先用可解释的 Jaccard 把链路跑通，有标注后再切 embedding 并对比，不做没数据支撑的优化 |
| 成本多少？ | `main.py` stats | 每天约 80 次短打分 + 8 次摘要，token 消耗很小；把打分和摘要拆开就是为了控成本 |
